# Graph Intelligence & Traversal Engine Specification

**Engine:** NetworkX `MultiDiGraph`  
**Module:** `backend/app/graph/`  
**Owner:** Member 2  
**Document Version:** 1.0.0

---

## 1. Graph Semantics & Topologies

The graph engine models on-chain economic activity as a directed multigraph $G = (V, E)$:

### Vertex Types ($V$)
- `SUSPECT`: Root wallet under active investigation.
- `INTERMEDIARY`: Intermediate transit or layering address.
- `DEPOSIT_WALLET`: Individual custodial deposit address generated by a VASP.
- `HOT_WALLET`: Omnibus pooling hot wallet owned and operated by a VASP.
- `MIXER`: Privacy pool or coin tumbler (e.g. Tornado.Cash).
- `BRIDGE`: Cross-chain bridge contract or minting gateway.
- `CONTRACT`: Generic smart contract or decentralized application.

### Edge Types ($E$)
- `TRANSFER`: Direct on-chain value movement (`from_address` $\to$ `to_address`).
- `SWEEP`: Consolidation sweep from a deposit wallet into an exchange hot wallet.
- `BRIDGE_ROUTE`: Cross-chain transition linking lock and mint events.

Each edge maintains:
- `tx_id`: Transaction hash.
- `asset`: Token symbol or native coin (e.g. `ETH`, `BTC`, `USDT`).
- `amount`: Transferred quantity.
- `timestamp`: Block confirmation time.
- `hop_distance`: Distance in edges from root suspect wallet.

## 2. Algorithms & Traversal Engine

1. **Breadth-First Search (BFS) Traversal**:
   - Traverses outward from suspect wallet up to user-configured depth (default: 3 hops, maximum: 5 hops).
   - Cycle prevention via visited set and path memoization.
2. **Noise Pruning & Dust Suppression**:
   - Transfers below configured dust threshold (e.g., $< 0.0001\text{ BTC}$ or $< 1.0\text{ USDT}$) are pruned unless they constitute $\ge 50\%$ of an address's outgoing volume.
   - High-degree omnibus hubs (hot wallets with thousands of edges) are aggregated into a single cluster node to prevent graph clutter.
3. **Path Analysis**:
   - **Shortest Path**: Computes minimum-hop path from suspect wallet to any identified VASP infrastructure.
   - **Strongest-Value Path**: Dijkstra-based path prioritizing highest cumulative value flow to destination exchanges.
